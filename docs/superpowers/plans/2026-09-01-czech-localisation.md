# Czech Localisation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Serve every page of the portfolio in Czech under `/cs`, with a language switch in the header, without moving a single existing URL.

**Architecture:** Locale-invariant data (slugs, URLs, posters, stack, ordering) stays single-source in `src/content/`; every human-readable string moves into two dictionaries that both satisfy one `Copy` type. Selector functions merge structure and copy back into the exact view models the components already consume, so components change only where they hardcode English. Routing uses two route groups with their own root layouts — `(en)` at the root, `(cs)` under `/cs` — so `<html lang>` is correct on both sides and everything stays statically prerendered.

**Tech Stack:** Next.js 16.3.1 (App Router), React 19, TypeScript, Tailwind v4, Vitest + Testing Library, Playwright.

**Spec:** `docs/superpowers/specs/2026-09-01-czech-localisation-design.md`

## Global Constraints

- **Never write `dark:` variants.** Dark is the default; both themes come from the semantic tokens in `src/app/globals.css` (`canvas`, `surface`, `raised`, `line`, `line-soft`, `text`, `muted`, `dim`, `accent`, `accent-soft`, `live`). A raw hex or a `dark:` prefix means a token is missing.
- **No emojis anywhere** — code, copy, or commit messages.
- **Before calling any task done:** `npm run build && npm run lint && npm test`. The build is what type-checks; Vitest transpiles without checking types.
- **`params` and `searchParams` are Promises.** Await them. `PageProps<"/work/[slug]">` and `LayoutProps<"/">` are globals generated by `next dev`/`next build`/`next typegen`, not imports.
- **Read `node_modules/next/dist/docs/` before writing routing code.** It is the authority for this version, not older Next.js knowledge.
- **Server Components by default.** `site-header.tsx` and `app-carousel.tsx` are the only Client Components; do not add more.
- **The name is `Vit Busek`, without diacritics,** in both languages — copy, metadata, and the title template.
- **No existing URL moves.** `/`, `/work`, `/work/:slug`, `/about`, `/contact`, `/privacy` stay exactly where they are. Route slugs stay English on both sides: `/cs/work/trader`.
- **No cookies, no `localStorage`, no middleware, no `Accept-Language` detection.** The privacy notice promises this and a test-visible contradiction is a bug.
- **Job titles stay English inside the Czech copy** ("Frontend Developer", "Team Leader"). Project titles are product names and are never translated.
- **Tests sit next to what they cover** (`src/**/*.test.tsx`); Playwright specs live in `e2e/`.
- **One PR per section.** Tasks 1-4 are PR 1, task 5 is PR 2, tasks 6-11 are PR 3. Commit after every task; open the PR at the end of its section.

```ts
import type { Copy } from "./copy/types";
import { CAROUSEL_ORDER, getProject, projects, type ProjectData, type ProjectSlug } from "./projects";

export type Metric = { label: string; value: string };

export type LocalisedProject = Omit<ProjectData, "metrics"> & {
  summary: string;
  role: string;
  highlights: readonly string[];
  metrics: Metric[];
  posterAlt?: string;
  liveNote?: string;
};

function merge(data: ProjectData, copy: Copy): LocalisedProject {
  const text = copy.projects[data.slug as ProjectSlug];
  if (data.metrics.length !== text.metricLabels.length) {
    throw new Error(
      `${data.slug}: ${data.metrics.length} metric values but ${text.metricLabels.length} labels`,
    );
  }
  const { metrics, ...rest } = data;
  return {
    ...rest,
    summary: text.summary,
    role: text.role,
    highlights: text.highlights,
    posterAlt: text.posterAlt,
    liveNote: text.liveNote,
    metrics: metrics.map((value, index) => ({ value, label: text.metricLabels[index] })),
  };
}

export function localiseProjects(copy: Copy): LocalisedProject[] {
  return projects.map((project) => merge(project, copy));
}

export function localiseProject(slug: string, copy: Copy): LocalisedProject | undefined {
  const data = getProject(slug);
  return data && merge(data, copy);
}

export function localiseCarousel(copy: Copy): LocalisedProject[] {
  return CAROUSEL_ORDER.map((slug) => {
    const project = localiseProject(slug, copy);
    if (!project) throw new Error(`carousel references unknown project: ${slug}`);
    return project;
  });
}
```

```tsx
"use client";

import Link from "next/link";
import { usePathname } from "next/navigation";
import type { Copy } from "@/content/copy";

/** "/cs/work/trader" -> "/work/trader", and "/work/trader" -> "/cs/work/trader". */
export function counterpart(pathname: string) {
  if (pathname === "/cs" || pathname.startsWith("/cs/")) {
    return pathname.slice(3) || "/";
  }
  return pathname === "/" ? "/cs" : `/cs${pathname}`;
}

export function LanguageSwitch({ copy }: { copy: Copy }) {
  const pathname = usePathname();
  const inCzech = pathname === "/cs" || pathname.startsWith("/cs/");
  const other = counterpart(pathname);

  return (
    <nav aria-label={copy.ui.languageSwitch.label}>
      <ul className="flex items-center gap-2">
        <Item code="EN" current={!inCzech} href={other} name={copy.ui.languageSwitch.en} lang="en" />
        <Item code="CS" current={inCzech} href={other} name={copy.ui.languageSwitch.cs} lang="cs" />
      </ul>
    </nav>
  );
}
```

`Item` is in the same file. The two-letter code is what a visitor sees; the language's own name is what a screen reader announces, and what the tests query by:

```tsx
function Item({
  code,
  current,
  href,
  name,
  lang,
}: {
  code: string;
  current: boolean;
  href: string;
  name: string;
  lang: string;
}) {
  if (current) {
    return (
      <li>
        <span aria-current="true" className="label text-accent">
          {code}
        </span>
      </li>
    );
  }
  return (
    <li>
      <Link
        href={href}
        hrefLang={lang}
        lang={lang}
        className="label text-muted transition-colors hover:text-accent"
      >
        <span aria-hidden>{code}</span>
        <span className="sr-only">{name}</span>
      </Link>
    </li>
  );
}
```

`sr-only` is Tailwind's built-in visually-hidden utility, so no new CSS is needed.
